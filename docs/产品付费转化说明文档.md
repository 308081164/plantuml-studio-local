# 产品付费转化说明（免费版产线 · 可行性）

本文档面向产品与工程，说明在现有「付费 / 激活版」基础上增加「免费版」产线的商业逻辑、技术边界，以及**支付环节是否可以不依赖服务器**的结论与推荐架构。

---

## 1. 版本与能力分层（建议）

| 维度 | 免费版（建议默认安装形态） | 激活版（密钥激活后） |
|------|---------------------------|----------------------|
| 安装后默认 | 是 | 用户输入有效激活码后切换 |
| 用户自写 PlantUML 源码并渲染 | 不限制（与您的目标一致） | 不限制 |
| 智能生成（LLM）等增值能力 | 可按策略限次或关闭 | 全功能 |
| **智能生成结果**的源码展示 | 加密展示、禁止复制（见 §3） | 明文、可复制 |
| **智能生成结果**的预览图 | 默认水印、禁止复制/导出/加入暂存（见 §3） | 无水印、可操作 |
| 单次「解锁当前图」 | 支付后解除上述限制（可选设计） | 不需要 |
| 画板编辑、导出等 | 可与免费策略绑定或仅激活版开放 | 全功能 |

说明：将「手写源码」与「智能生成管线」在规则上拆开，既符合您「自行输入生图不受限」的诉求，又能在智能生成路径上保留转化空间，工程上也更清晰。

## 2. 支付宝支付 0.8 元「解锁本图」——不依赖服务器是否可行？

### 2.1 结论（简要）

- **严格意义上的「完全不依赖任何服务器」与支付宝官方支付流程不可兼得。**  
  原因：App 支付 / 手机网站支付 / 当面付等均需与支付宝开放平台交互；**异步通知、订单查询、签名校验**等能力均以云端或至少「可验证的受信环境」为前提。
- **可实现的折中**包括：  
  1. **极轻量自有服务端**（推荐）：只负责创建订单、接收支付宝异步通知、签发**短期解锁令牌**（绑定设备指纹 + 图像哈希 + 过期时间），客户端凭令牌本地解密或解除 UI 限制。  
  2. **第三方收银台 / SaaS**：将支付与履约交给可信第三方，客户端只验证第三方返回的签名票据——本质上仍是「依赖外部服务」，只是您不自建。  
  3. **非支付宝的离线解锁**（卡密、预购兑换码）：可完全离线验码，但**不是支付宝收款**，合规与运营需单独设计。

### 2.2 若坚持「客户端单机」的风险

- 伪造支付成功、篡改本地「已支付」标记：没有服务端参与时，**无法密码学证明用户真实付款**。  
- 任何「本地校验支付截图 / 本地解析回调」的方案都易被重放或伪造。  
- **结论**：若商业上必须绑定「支付宝 0.8 元」这一真实资金流，应规划**最小后端**或可信第三方；单机仅适合「卡密 / 捐赠码 / 预置授权」类模型。

## 3. 「源码加密不可复制、图像水印且不可复制导出」——技术可行性说明

### 3.1 客户端加密的边界

- 在纯本地应用中，**加密密钥与解密逻辑都在用户机器上**；所谓「加密」对专业用户而言多为**提高成本**（混淆、反调试、分模块），而非绝对安全。  
- 合理预期：**防普通用户随手复制**有效；**防恶意逆向**需结合代码保护、许可证与（可选）服务端下发密钥分片。

### 3.2 水印

- 技术上可行：在渲染管线对位图叠加水印，或对 SVG 注入半透明层。  
- 「不可复制」在 Electron/WebView 中可通过禁用右键、屏蔽剪贴板写入、使用 `user-select: none` 等**提高门槛**；对截屏、外接录屏无法从技术根除，需产品话术与法律条款配合。

### 3.3 与「手写源码不限」的并存

- 建议在数据模型中区分：`sourceOrigin = 'user' | 'agent'`，仅对 `agent` 路径应用加密展示与导出限制，避免误伤手写场景。

## 4. 推荐的产品转化路径（与工程对齐）

1. **默认免费版安装**：首次启动明确展示能力差异与隐私说明（智能生成是否联网等）。  
2. **激活版**：沿用现有「设备码 + 激活码」体系，密钥激活后全功能、无水印、可导出暂存。  
3. **小额解锁（0.8 元）**（若采用）：  
   - 用户点击「解锁当前智能生成图」→ 调起支付宝 → **服务端**（或函数计算）验签后发**短期令牌** → 客户端写入本地并在令牌有效期内解除限制。  
4. **合规**：展示《用户协议》与《隐私政策》，说明支付与日志、设备标识的用途与保留期限。

## 5. 与本仓库当前实现的关系

- 当前代码库已实现本地渲染、暂存区、画板（mxGraph）等能力；**免费版 / 支付 / 令牌**尚未作为产品模块落地。  
- 本文档用于指导后续迭代的需求拆分：**许可证状态机、渲染管线分支、UI 限制与支付回调服务**应分阶段实施。
